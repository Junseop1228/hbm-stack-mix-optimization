## 2. ★ 과제 T1 (최우선) — β 재조사

### 문제

현재 β = 0.95는 **CATCH 논문(IEEE TCAD 2025)의 범용 칩렛 coverage sweep 값**이다. HBM KGD 테스트의 실측 검출률이 아니다. 06_Parameters Y3에 "함수 형태는 버리고 값만 승계"라고 적어뒀는데, **그 승계가 무리였을 가능성이 있다.**

### 왜 문제인가 — 계산으로 드러났다

β별로 "매 층마다 검사해도 도달하는 최소 출하 불량률"을 계산했다.

| β | 최소 달성 DPPM (k=1, L=12, x=0.965) |
|---|---|
| **0.950 (현재값)** | **1,909 ppm** |
| 0.990 | 366 ppm |
| 0.995 | 182 ppm |
| 0.999 | 36 ppm |

**실제 HBM 업계 DPPM 목표는 수십~수백 ppm 수준이다.** 우리 모델은 1,909 ppm이 하한이라 **한 자릿수 이상 느슨하다.** β = 0.95로는 아무리 자주 검사해도 업계 수준을 못 맞춘다.

### 조사할 것

| # | 대상 | 검색 방향 |
|---|---|---|
| 1 | **HBM/DRAM KGD 테스트의 실제 test coverage 또는 escape rate** | KGD test coverage, DPPM target, test escape rate DRAM |
| 2 | **HBM 출하 DPPM 목표치** | HBM quality target DPPM, automotive vs datacenter grade |
| 3 | 인서션 종류별 검출 특성 | pre-bond / mid-bond / post-bond test coverage 차이 |

**우선 볼 곳**: SemiEngineering "HBM Shifts Testing Left"(2026-05-12), Advantest·Teradyne·FormFactor·Aehr Test 기술자료, JEDEC JESD270 계열, ITC/VTS 논문.

### 판정 규칙

- **HBM 전용 근거를 찾으면** → β 기준값·범위를 그것으로 교체하고 등급 B로 올린다
- **못 찾으면** → 정직하게 "미확보"로 두고 **범위를 0.95~0.999로 확대**한다. 그리고 **"업계 DPPM 수준을 만족하려면 β ≥ 0.995가 필요하다"를 모델의 산출 결론으로 격상**한다

### 후자가 오히려 좋은 결과일 수 있다

> **"HBM 품질 수준을 만족하려면 검출 정확도가 99.5% 이상이어야 하고, 검사 빈도로는 절대 보완할 수 없다."**

이건 시나리오 D에서 이미 방향이 나왔다(β = 0.84면 매 층 검사해도 실행 불가). **검사 장비 투자와 검사 횟수 증설이 대체재가 아니라는 정량 결론**이며, 실무적으로 의미가 크다. 단 **β의 근거가 범용 칩렛 값인 채로는 주장할 수 없다.** 그래서 T1이 최우선이다.

### 수정 위치

- `src/hbm_model.py` → `Params.beta` 기준값
- `src/scenarios.py` → `DIST["beta"]` 삼각분포
- `../docs/06_Parameters.md` → Y3 행과 근거 서술

## 3. ★ 과제 T2 (최우선) — DPPM 상한을 시나리오 G로 승격

### 문제

`src/scenarios.py`의 `DPPM_CAP = 5000.0`은 **내가 만든 숫자다. 근거가 없다.** 그런데 이 값이 결론을 크게 흔든다.

| DPPM 상한 | 최적 해 |
|---|---|
| 1,200 / 1,500 ppm | **실행 불가** |
| 2,000 ppm | 8단k1 66% + 12단k1 28% + 16단k2 6% — **매 층 검사** |
| 3,000 ppm | 8단k1 38% + 16단k2 62% |
| **5,000 ppm (현재)** | 8단k2 48% + 12단k2 20% + 16단k4 32% |
| 8,000 ppm 이상 | 12단k2 58% + 16단k4 42% (사실상 제약 없음) |

**상한을 바꾸면 최적 검사 주기가 k=4에서 k=1로 통째로 이동한다.**

### 왜 치명적인가

**⚠️ 2026.08.12 S-1 정정** — 이 절이 근거로 삼았던 "제품 믹스를 만드는 것은 품질 제약(C4)이다"는 **귀속 오류였다** (08_Handoff 3.6, 07_Results 3절). 믹스의 뼈대는 본더·테스터 두 캐파 제약의 동시 구속이고, **C4가 제약하는 것은 검사 주기 k다.**

**그래도 T2는 그대로 유효하며, 오히려 표적이 선명해졌다.** 위 표가 보여주듯 상한을 바꾸면 최적 k가 k=4에서 k=1로 통째로 이동한다. **검사 주기를 결정하는 유일한 제약의 수치가 근거 없는 상수로 박혀 있다는 것이 문제다.** 검사 주기 k는 이 프로젝트의 결정변수 절반이다.

### 할 일

1. **HBM DPPM 목표치의 실제 근거를 찾는다** (T1과 함께 조사 — 같은 자료에 같이 나올 가능성이 높다)
2. **시나리오 G를 신설한다.** DPPM 상한을 스윕하고 최적 검사 주기 k의 전환점을 도출한다
3. 실행 불가 구간(현재 1,500 ppm 이하)의 경계를 정밀화한다. **"이 검출률로는 이 품질을 못 만든다"는 경계선 자체가 결과다**
4. `../docs/06_Parameters.md` 7절 시나리오 표에 G를 추가하고, `../docs/09_Roadmap.md` 6.1 대표 그림 목록에 넣을지 판단한다

### 수정 위치

- `src/scenarios.py` → `DPPM_CAP` 상수를 스윕 변수로. 시나리오 G 블록 추가
- `../docs/06_Parameters.md` → 7절 시나리오 매핑에 G 행 추가, 6절 미확보 목록에 DPPM 상한 추가
- `../docs/01_Spec.md` → 5절 시나리오 표에 G 추가

## 4. 과제 T3 (즉시, 5분) — c_test 정정

`../docs/06_Parameters.md` T18은 인서션당 유닛당 $2~5 → **무차원 0.007~0.017**로 정해뒀다. 그런데 코드는 **0.05**를 쓴다. **범위 상한의 3배다.** 내 실수다.

### 영향은 확인했다 — 없다

- c_test = 0.012 → J = 0.17214, 믹스 8단k2:48% + 12단k2:20% + 16단k4:32%
- c_test = 0.050 → J = 0.17103, 믹스 **완전 동일**

Phase 3 정보가치 분석에서 c_test 상관이 0.038(사실상 0)이었던 것과 일치한다. 몬테카를로도 0.007~0.10을 샘플링해 참값 구간을 포함했다.

### 그래도 고친다

문서와 코드가 어긋난 채로 두면 이후 판단의 근거가 무너진다.

- `src/hbm_model.py` → `Params.c_test` 기준값을 **0.012**로
- `src/scenarios.py` → `DIST["c_test"]`를 (0.007, 0.012, 0.017)로 축소
- 정정 후 Phase 2·3 재실행하고, **결론이 안 바뀌었음을 로그로 확인**한다

## 5. 과제 T4 — θ와 a의 문헌 근거 보강

두 값은 공개 자료에 절대값이 없다. 범위라도 좁혀두면 삼각분포의 폭이 줄어 신뢰구간이 좁아진다.

### θ = t_test / t_stack

이미 확보한 조각들이다.

| 항목 | 값 | 출처 |
|---|---|---|
| 테스터 UPH 공식 | UPH = P × 3600 / (ST + TT + IT) | US 11448688 |
| 병렬 site 수 P | 64 ~ 128 | SemiEngineering 2026-05-12 |
| HBM 전용 ATE | Teradyne Magnum 7H, 처리량 1.6배 향상 | electronicsforu 2025-08-05 |
| HBM4 테스트 속도 요구 | HBM3E의 2배 | Teradyne |

**t_test 절대값은 미확보다.** UPH 공식에 병렬도를 넣어 역산하는 경로가 있으나 ST/TT/IT 값이 없다.

**조사 방향**: HBM 스택 1회 인서션의 초 단위 테스트 시간, 또는 KGD 테스트의 스택당 UPH.

### a = t_fix_a / t_stack

t_fix_a는 **적층 전 고정 작업**(캐리어 로딩·언로딩, 최초 정렬)이다. 층별 배치·가고정은 t_stack이고, mass reflow·몰딩은 t_fix_b로 별개다.

**조사 방향**: TCB 본더의 로딩·정렬 시간, 웨이퍼/캐리어 핸들링 오버헤드, ±100nm급 정렬에 걸리는 시간.

**이미 확보**: TCB 툴 배치 속도 시간당 500~1,000 die(SemiAnalysis) → t_stack 3.6~7.2초 역산. gang bonding 개별 1초 + 동시 열압착 5~10초(US 9524958).

### 임계값 — 조사 결과를 대조할 기준

| 전환 | 임계 a | t_stack=5.4초 환산 |
|---|---|---|
| 8단 → 12단 | **1.40** | t_fix_a ≈ 7.6초 |
| 12단 → 16단 | **10.32** | t_fix_a ≈ 56초 |

문헌에서 나온 범위가 이 경계 어디에 떨어지는지가 곧 결론이다.

## 6. 과제 T5 — 수요 세그먼트 정의 확정

`src/scenarios.py`의 `make_demand()`가 **"달성 가능 물량의 40%는 8단 이상, 18%는 12단 이상"**으로 자동 보정한다. 완전히 임의다. Spec 10절 4번 미확정 항목이다.

### 확보된 근거

| 항목 | 내용 | 출처 |
|---|---|---|
| GPU당 HBM 슬롯 | **8개 고정** | Wing VC 2026-05-12 |
| B200 | 24GB × 8 = 192GB | 동일 |
| B300 | HBM3E 12단 = 288GB | 동일 |
| Rubin | 288GB HBM4, 12단 | NVIDIA 2026-07-21 |
| **Rubin Ultra** | 원래 12단 HBM4e → **8단 HBM4e / 12단 HBM4 / 8단 HBM4 확대 검토. 최종 스펙 미정** | TrendForce 2026-08-04 |
| 하향 시 영향 | Ultra가 2027년 HBM 비트 수요의 20%, 384→192GB면 업계 비트 수요 약 10% 감소 | 시장 분석 2026-08 |

**세그먼트를 강제하는 것은 총 용량 목표다.** 슬롯이 8개로 고정이므로 스택당 용량이 목표÷8 이상이어야 하고, 이것이 최소 층수를 정한다.

### 할 일

1. GPU 제품별 총 용량 목표에서 **역산해 세그먼트를 3개 이하로 정의**한다 (예: 192GB급 / 288GB급 / 384GB급)
2. 각 세그먼트의 비중을 **공개 출하량 추정으로 근거 있게** 잡는다. 못 찾으면 균등 가정 + 민감도
3. `../docs/06_Parameters.md` 4절에 세그먼트 표를 신설한다

**이건 프로젝트 시의성의 핵심 근거이기도 하다.** 고객이 공급 제약 때문에 층수를 낮추는 협상을 지금 하고 있고 답이 안 정해졌다.

### 8.2 ★ 2026.08.12 — 방법론 프레이밍 확정

**Block T(설비·원가) 계수는 공개 자료에 없다.** 절대값이 전부 비공개이므로 실측 확보 경로가 없고, 이는 결함이 아니라 **처음부터 `../docs/01_Spec.md` 8.2에 명시된 전제**다.

> **이 연구의 입력은 데이터셋이 아니라 파라미터 공간이다.** 공개 문헌으로 확보 가능한 범위를 삼각분포로 두고 확률적으로 보고한다. 결론은 점추정이 아니라 **임계 조건과 신뢰구간**이다.

**즉 "값이 없어서 못 했다"가 아니라 "애초에 그렇게 설계했다"가 맞는 서술이다.** 몬테카를로 2,000회가 그 설계의 실행이다.

**귀결 2가지**

**① T4(θ·a 문헌 조사)를 S3.7로 승격한다.** 실측이 불가능하므로 **공개 문헌으로 범위를 좁히는 것이 유일한 경로**이며, 선택 과제가 아니라 필수다.

**② 파라미터 표에서 "확인 대기" 성격의 표기를 전부 제거한다**(1절). 오지 않을 값을 기다리는 것처럼 보이는 표기를 남기지 않는다. 미확보는 **시나리오 범위**로 명시한다.

## 10. 절대 되돌아가지 말 것

`08_Handoff.md` 7절의 폐기된 차별점 8개, 그리고 아래 확정 사항을 다시 뒤집지 마라.

| 확정 사항 | 되돌리면 안 되는 이유 |
|---|---|
| **목적함수 = 총이익 최대화** | 분수형은 규모 무관이라 캐파 듀얼이 0으로 붕괴한다 (Spec 3.7.1) |
| **캐파 축 = a**, φ_capacity 폐기 | φ_capacity는 정의에 L_ref가 들어가 순환한다 |
| **escape는 매출 미계상, DPPM에는 계상** | COPQ 표준 처리. 04_Interface 4절에 가정 명시됨 |
| **E[layer]를 L로 근사 금지** | 임계 a가 약 4배 과대평가된다. 닫힌형 E[layer] = (1 − x^L)/(1 − x) |
| **파라미터 MC 유지 / 사건 MC 폐기** | 서로 다른 몬테카를로다. Roadmap 6.1.1 |
| **DES는 범위 외** | 시뮬레이션 키워드는 별도 트랙. Roadmap 7절 |
