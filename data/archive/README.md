# 정정 전 로그 보존

이 폴더의 세 파일은 **`src/run_all.py` 가 만들지 않는다.** 현행 파이프라인의 산출물이 아니라, 파라미터 정정이 결론을 바꾸지 않았음을 보이기 위해 남겨둔 **정정 직전 상태의 기록**이다.

| 파일 | 원본 |
|---|---|
| `gate0_log_pre_ctest.txt` | Gate 0 |
| `phase2_log_pre_ctest.txt` | Phase 2 |
| `phase3_log_pre_ctest.txt` | Phase 3 |

---

## 무엇을 정정했는가

검사 1회 비용 `c_test` 기준값이 코드에 **0.05** 로 들어가 있었다. 그런데 `docs/06_Parameters.md` T18 이 정한 범위는 **0.007 ~ 0.017** 이다. 상한의 3배였고, 문서와 코드가 어긋난 상태였다.

`c_test = 0.012` 로 정정하고 Gate 0 · Phase 2 · Phase 3 을 전량 재실행했다.

## 결론은 바뀌지 않았다

| 지표 | 정정 전 (0.05) | 정정 후 (0.012) |
|---|---|---|
| 병목 전환점 H_t/H_b | 0.8661 | **0.8661** (동일) |
| 임계 a (8→12 / 12→16) | 1.40 / 10.32 | 1.39 / 10.26 |
| 단일 풀 shadow price (검증 8) | 0.20754 | 0.20840 — 직접 계산과 일치, **통과** |
| 기준 시나리오 J | 0.17180 | 0.17289 |
| 몬테카를로 실행가능 | 1,316 / 2,000 (65.8%) | **1,316 / 2,000 (65.8%)** (동일) |
| x → 16단 상관 | +0.537 | +0.538 |
| θ → 병목 상관 | +0.450 | **+0.450** (동일) |
| c_test 자체 상관 | −0.038 | −0.032 |

정보가치 순위(x 1위, 병목은 θ 1위)도 그대로다. **`c_test` 는 의사결정에 개입하지 않는다는 Phase 3 의 사전 판정이 실측으로 재확인됐다.**

---

## ⚠️ 현행 로그와 직접 비교하지 말 것

이 로그들은 **`β_f = 0`(최종 검사 미도입) · `DPPM cap = 5,000 ppm` · 이전 수요 정의** 설정에서 산출됐다. 이후 다음 세 가지가 추가로 바뀌었다.

1. 최종 검사 검출률 `β_f = 0.95` 도입
2. DPPM 상한 5,000 → **200 ppm**
3. 수요 세그먼트를 GPU 용량 목표에서 역산해 절대 상수로 고정

그래서 `data/` 의 현행 로그와는 수치가 다르다. 예컨대 몬테카를로 실행가능률은 이 로그에서 65.8%, 현행 65.8% → **47.6%** 다. 이는 `c_test` 정정 때문이 아니라 **DPPM 상한을 조인 결과**다.

**현행 수치의 정본은 `docs/07_Results.md` 1절이다.**
